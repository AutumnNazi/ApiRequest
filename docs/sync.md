# 协作与同步（WebDAV，已实现）

[English](./en/sync.md) | 简体中文

> **状态：已实现（2026-07-26）**。采用 **WebDAV** 方案——用户自带任意 WebDAV 服务（坚果云 / Nextcloud / 自建），项目方无需运行服务端。与 Joplin / Floccus 等开源工具同一模式。原占位设计中的 oplog 推送留作未来实时协作的演进方向。

相关文档：[文档索引](./index.md) · [数据模型](./data-model.md) · [安全与运维](./ops.md)

## 方案

- **本地优先**：所有数据先落本地 SQLite；同步是可选叠加层，手动触发（顶栏 ⇅）。
- **存储形态**：远端每工作区一个快照文件 `ApiRequest/workspace-<id>.json`（完整状态快照，而非 oplog——快照对 WebDAV 这类"哑存储"更稳，无需服务端合并逻辑）。
- **传输**：极简 WebDAV 客户端（GET/PUT/MKCOL + Basic auth），见 `backend/sync/dav.go`。

## 合并算法（实体级 LWW）

一次同步 = 拉远端 → 合并 → 写回本地 → 推合并结果：

1. **节点**（集合/文件夹/请求）：同 id 比较 `rev = max(updatedAt, deletedAt)`，大者胜；对方独有的保留。
2. **删除传播**：软删除即墓碑（`deleted_at`），墓碑参与 LWW——删除晚于修改则删除胜出，不会"复活"。
3. **环境**：同 id LWW（`updatedAt`）；`is_active` 不同步（激活状态是本机 UI 状态）。
4. **全局变量**：使用独立的 `updated_at` 作为整体 rev，按整组变量执行 LWW。
5. **冲突粒度**：实体级——两台设备改同一请求的不同字段时，晚写入者整体覆盖。字段级合并 / CRDT 留待后续评估。

## 敏感数据

- 设置中可勾选**不上传密钥变量的值**（`OmitSecrets`）：上传前剥离请求/集合 Auth 凭据及 `type=secret` 变量的 value（保留键名占位），并在 v2 快照写入 `secretsOmitted: true`；仅带该标记的空占位会在拉取合并后按实体 ID、变量 key 与同名序号补回本地已有值，未带标记的空值表示用户明确清空。各设备自行维护密钥。
- WebDAV 密码与请求凭据优先存入系统 keychain；系统 keychain 不可用时，使用 Argon2id + AES-GCM 加密文件回退。SQLite 仅保存 `secret://...` 引用。

## 版本与容错

- 当前快照 `schemaVersion` 为 2；远端版本更新时拒绝合并并提示升级客户端。v1 快照没有 `secretsOmitted` 元数据，为兼容旧版“不上传密钥”行为，空密钥按已剥离占位保守处理。
- 快照 GET/PUT 均限制为 64 MiB，超限会明确拒绝，不会静默截断后继续合并。
- 远端 401/403 给出明确的认证失败提示；404 视为首次初始化，直接上传。
- 同步结果报告：推送/拉取/删除数与远端路径，前端顶栏展示。

## 已知限制（后续演进）

- 无自动定时同步（手动触发）；无同步前互斥锁——两端同时 PUT 时后写覆盖（LWW 语义下可接受，极端并发下可能丢一轮对方快照，下轮同步找回）。
- Cookie、历史记录不参与同步（属本机运行时数据）。
- 远端快照路径由本地 `workspaceId` 决定。当前桌面端只同步已存在的本地工作区，不会发现或导入远端工作区；多设备复用同一快照时必须保留相同的工作区 ID（例如迁移本地数据目录）。
