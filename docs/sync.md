# 协作与同步（WebDAV，已实现）

[English](./en/sync.md) | 简体中文

> **状态：已实现（2026-07-26）**。采用 **WebDAV** 方案——用户自带任意 WebDAV 服务（坚果云 / Nextcloud / 自建），项目方无需运行服务端。与 Joplin / Floccus 等开源工具同一模式。原占位设计中的 oplog 推送留作未来实时协作的演进方向。

相关文档：[文档索引](./index.md) · [数据模型](./data-model.md) · [安全与运维](./ops.md)

## 方案

- **本地优先**：所有数据先落本地 SQLite；同步是可选叠加层，手动触发（顶栏 ⇅），也可设置自动间隔（见下）。
- **存储形态**：远端每工作区一个快照文件 `ApiRequest/workspace-<id>.json`（完整状态快照，而非 oplog——快照对 WebDAV 这类"哑存储"更稳，无需服务端合并逻辑）。
- **传输**：极简 WebDAV 客户端（GET/PUT/MKCOL + Basic auth），见 `backend/sync/dav.go`。

## 合并算法（字段级三路合并，ADR-017）

一次同步 = 拉远端 → 合并 → 写回本地 → 推合并结果：

1. **基线**：本地持久化"上次合并基线"（`sync_base` 表，每工作区一份、未剥密钥），作为三路合并的公共祖先；每次同步完成本地写入后更新为合并结果。推送失败也保留基线——远端仍是旧快照，下轮按差量重新并入，不丢数据。
2. **节点内容字段**（name/request/auth/variables/preScript/testScript/sortOrder）：三路逐字段合并——request 内部再逐键递归（headers/params 等数组整体为一个键）；本地与基线一致采远端，远端与基线一致采本地，双端同改同一字段 → **本地胜出**并记入冲突清单，同步结果面板列出明细（实体、字段、两端值预览）。合并结果对两侧都有变更时双向计数。
3. **结构性操作保持实体级 LWW**：软删除墓碑（`deleted_at`，删除晚于修改则删除胜出，不"复活"）与移动（parent 变更随 `rev = max(updatedAt, deletedAt)` 新者）；无基线（首次同步/升级后第一轮/基线损坏）时该轮整体回退实体级 LWW 并重建基线。
4. **环境**：name 与 variables 逐字段三路；`is_active` 不同步（激活状态是本机 UI 状态）。
5. **全局变量**：维持整组 LWW（独立 `updated_at` 作为整体 rev），不逐字段。
6. **兼容**：基线按快照 `schemaVersion` 校验，版本不符自动清除重建；对端旧版本无基线语义不受影响（对方按自己的基线/回退逻辑独立合并）。

## 敏感数据

- 设置中可勾选**不上传密钥变量的值**（`OmitSecrets`）：上传前剥离请求/集合 Auth 凭据及 `type=secret` 变量的 value（保留键名占位），并在 v2 快照写入 `secretsOmitted: true`；仅带该标记的空占位会在拉取合并后按实体 ID、变量 key 与同名序号补回本地已有值，未带标记的空值表示用户明确清空。各设备自行维护密钥。
- WebDAV 密码与请求凭据优先存入系统 keychain；系统 keychain 不可用时，使用 Argon2id + AES-GCM 加密文件回退。SQLite 仅保存 `secret://...` 引用。

## 版本与容错

- 当前快照 `schemaVersion` 为 2；远端版本更新时拒绝合并并提示升级客户端。v1 快照没有 `secretsOmitted` 元数据，为兼容旧版“不上传密钥”行为，空密钥按已剥离占位保守处理。
- 快照 GET/PUT 均限制为 64 MiB，超限会明确拒绝，不会静默截断后继续合并。
- 远端 401/403 给出明确的认证失败提示；404 视为首次初始化，直接上传。
- 同步结果报告：推送/拉取/删除数与远端路径，前端顶栏展示。

## 已知限制（后续演进）

- ~~无自动定时同步~~ 已支持（设置页配置间隔，分钟级；0 = 关闭）：应用内每 30 秒检查一次到期，按工作区独立触发；失败也计入间隔（防 30s 重试风暴），完成时顶栏轻提示并刷新本地数据。同一工作区本地并发触发会直接报"已在进行中"（不排队），跨设备互斥经 WebDAV 条件写入实现：PUT 快照时携带拉取时的 ETag（If-Match），远端已被并发修改（412）则自动重拉、重合并、重推（最多 3 轮）；服务器不支持 ETag 时退化为无条件写（后写覆盖，LWW 语义下可接受）。
- Cookie、历史记录不参与同步（属本机运行时数据）。
- ~~远端工作区发现/导入~~ 已支持：设置页同步分区可列出远端 `ApiRequest/` 下的工作区快照（PROPFIND）并一键导入——本地沿用远端工作区 ID 建立工作区、导入实体并写入合并基线，导入后即可常规双向同步。注意：远端路径仍由 workspaceId 决定，已同步多设备的用户不要随意改本地工作区 ID。
