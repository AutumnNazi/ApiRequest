# 协作与同步（可选叠加层）

> **状态：占位设计**。同步排期在 Phase 5（见 [ADR-011](./decisions.md#adr-011-协作同步grpc-排期靠后)），本篇只固定影响前期设计的原则性约束（oplog 表结构、密钥不上传）；协议细节、服务端形态与冲突合并算法在 Phase 5 开工前展开成完整设计。

相关文档：[文档索引](./index.md) · [数据模型](./data-model.md) · [安全与运维](./ops.md)

- 本地优先：所有数据先落本地 SQLite。
- 同步层作为独立模块，把集合/环境变更以操作日志（[oplog](./data-model.md#数据库-schema-设计)）形式推送到远程服务。
- 冲突处理：以实体为粒度做"最后写入优先 + 变更记录"，复杂合并留待后续（可引入 CRDT）。
- 敏感数据：环境中的密钥变量本地加密存储，同步时可选择不上传密钥值。
- 同步状态经 `sync:status` 事件推前端（见[接口约定](./api-contract.md#5-事件go--前端经-runtimeeventsemit)）。
